# 云电脑 Codex

在没有 GUI 的 Linux 服务器上，设备助手连接原生 Codex app-server，AIO Agent 用 Topcoat 显示会话。服务器无需 Electron、显示器、VNC 或远程桌面；模型、工具、Skills、MCP、原生审批和会话存储由安装的 Codex 负责。

## 完整界面目标与当前覆盖

产品目标以当前 Codex Desktop 加 Buddy 的完整界面和功能为参照。Topcoat 迁移现有 AIO Agent 页面只是基础，不能当成完整复刻验收通过。CLI 模式使用原生执行引擎，但不会从 CLI 获得 Desktop 的私有界面和主进程服务；Topcoat 界面仍需维护原生协议与交互映射。

| 能力 | 当前实现 | 完整对齐仍需验证或补齐 |
| --- | --- | --- |
| 设备与项目 | 统一 AIO 入口、云电脑选择、授权目录、自动局域网选路 | 公网配对后的完整操作验收 |
| 会话 | 新建、恢复、归档、命名、分页、流式输出、停止；新增分支、历史回退、压缩及归档恢复 | 新增操作的生产验收、原版项目侧栏 |
| 原生工具 | Codex 执行命令、编辑文件、加载 Skills/MCP；新增授权目录内的文件浏览和文本查看 | 附件上传、Git diff/review、终端面板 |
| 审批与提问 | 转发当前连接收到的原生审批及结构化问题 | 与原版全部审批种类、权限展示及无障碍交互逐项核对 |
| 设置与生态 | 原生模型列表、已加载 Skills；保留 AIO 设置页 | 原生账号、MCP、插件、自动化、连接及各设置页 |
| Buddy | 可复用设备已运行的 Buddy Host 所提供的执行路由 | Buddy 模型路由、供应商、Harness、委派、翻译及注入面板 |
| 多窗口 | 每页独立连接、关闭页面只释放自身视图 | 多浏览器真实运行、跨端事件与审批归属验收 |

桌面桥接是另一条已有路径：读取设备安装包的原始 JS/CSS，桥接 Desktop 主进程，网页运行真实界面，不是屏幕视频。它需要持续运行的 Desktop/Buddy。虚拟显示器只能补显示服务，不能补缺失的桌面包、系统调用或运行库。Buddy 仓库的 Linux Desktop 路径要求 glibc 2.35 及 pidfd；旧内核容器与宿主共用内核，因此不能仅换容器镜像就宣称支持完整原版运行时。

## 接入

先在服务器安装并登录原生 Codex CLI，再运行：

```sh
aio device connect --server https://aio.addzero.site --root /path/to/workspaces --no-browser
aio device codex-cli-enable --root /path/to/workspaces --codex-bin /path/to/native/codex
```

在已登录的 AIO 中批准配对后，「智能体 → 对话 → 执行设备」显示「云电脑」。选择授权根目录中的项目，新建或恢复会话即可发送任务。`--codex-bin` 必须是原生 CLI，不是 Buddy 进程代理脚本。设备已有 app-server 时复用它，不为浏览器重启原生运行时；没有运行时则通过原生 daemon 启动命令启动。

需要包含 headless 能力的宿主与设备助手 0.13.0。CLI 的实际发布状态须另行核对；安装本地候选包不等于 npm 发布。Root Linux 使用系统级 systemd 服务，普通 Linux 用户使用用户服务。

原生工作区接口已在 Codex CLI 0.162.0 上验证。历史列表使用该版本的 `useStateDbOnly` 索引查询；分支固定 `deferGoalContinuation`，不会自动继续源会话的目标。旧版本或后续协议变化仍需兼容性验证。

## 传输和授权

浏览器始终从 `https://aio.addzero.site` 进入，复用宿主的设备选路：优先探测已信任的局域网地址，失败回退公网。浏览器的本地网络权限仍由用户控制。每个页面申请短期、绑定设备和用户的视图票据，打开自己的 WebSocket；URL 不是可任意转发的代理。配对和能力撤销会关闭连接。

设备仅暴露明确的原生方法与参数。项目路径经 canonicalize 校验，必须在用户授权根目录内；历史会话按实际 cwd 再次校验，浏览器不能覆盖设备 sandbox、approval 或配置。每个设备最多四个独立视图，关闭一个页面不会主动停止任务或关闭其他页面。对同一会话同时输入仍服从原生 Codex 并发规则，不能把它理解为四份独立任务状态。

## 页面能力

- 模型列表、项目目录、新建/恢复/归档/命名会话、历史分页。
- 流式回复、命令与文件变更回执、错误显示、停止任务、断线后的显式重连。
- 命令、文件和权限审批，以及结构化问题和 MCP elicitation。URL 授权提供复制链接与完成后继续；复杂表单字段保留原生 JSON 输入。
- URL 保存设备、项目和会话，支持刷新与多窗口；审批只由收到该请求的连接提交一次。
- 项目文件通过原生 `fs/readDirectory`、`fs/readFile` 读取，设备校验绝对路径、符号链接和授权根目录；只预览不超过 1 MiB 的 UTF-8 普通文件。文件详情、目录和归档列表可以用外层 URL 恢复。
- 会话分支、历史回退、压缩和归档恢复使用原生接口。回退前确认其只改变会话历史、保留项目文件；分支不自动继续原目标。历史列表使用原生索引，当前尚未进入索引的分支保留侧栏入口。工作区更新期间阻止重复提交。

普通 Agent 对话继续保留原有服务配置、Memory、工具任务、Skill 同步与设置页面。云电脑的本机 Skills/MCP 由 Codex 配置加载，AIO Memory 与 Skill 页面不会自动变成原生配置同步服务。原版 Codex/Buddy 的设置界面、图形桌面操作与尚未开放的协议属于完整目标中的待实现能力。更新 Codex 后需检查原生协议兼容性，不能保证任意未来版本无需适配。
