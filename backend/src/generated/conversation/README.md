# 会话与模型

`models` 通过已授权 API 基址的 `GET /models` 读取模型 ID，复用密钥隔离、出站配额和宿主 broker；切换会话模型时锁定会话并检查排队及生成状态，只修改后续轮次使用的绑定，保留消息历史。

Controller 只处理传输；Service 是行为契约；模型、存储、模型传输和后台生成分别负责单一职责。

`intake` 先保存加密原文和请求指纹，普通消息表只写回执或净化内容；`memory` 负责受信跨插件调用、检索和来源可见性校验；`worker` 分开推进收件交付与后台模型整理。前台生成可抢占整理，不消耗模型失败重试次数。原文不进入生成器、历史上下文或普通日志。

Agent 数据库只保存本插件的数据。租约、空间角色、秘密授权、知识修订及来源依据由 Memory 事务校验；工作进程不能获取秘密明文。

`model_access` 集中校验个人模型和空间授权并解密模型凭据，供前台问答与后台整理复用。未指定会话模型时读取空间当前绑定；未配置则保持收件可用。

前台生成和后台整理共用 runtime 执行桥。memory_tools 仅为当前会话绑定空间提供净化检索，Pi 原生扩展触发工具调用后重新鉴权，并把返回的来源、命中与邻域合并到当前回复。后台整理不启用工具。
